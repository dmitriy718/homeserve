# Review pass 1 — correctness and maintainability

Date: 2026-08-11  
Depth: 1× baseline  
Perspective: local correctness, operator ergonomics, and documentation accuracy

## Scope and method

Reviewed every tracked source/configuration path, ran the repository validator, ShellCheck, Python compilation, Compose rendering, Prometheus validation, JSON parsing, and a targeted scan for unsafe placeholders and unpinned images. This pass focused on direct, locally provable defects rather than cross-service threat modeling.

## Findings and fixes

### P1-01 — Status could not report successful backups

- Severity: medium
- Finding: `backup.sh` makes `/srv/backups/local` root-only (`0700`), while `status.sh` normally runs as `dima` and tried to search that directory. It therefore reported no backup even after a successful archive.
- Fix: successful backups now atomically publish a non-secret `0644` status record under `/srv/ai-node/data/backup-status/last-success`. `status.sh` reads that record and reports the verified archive and age without elevated access.

### P1-02 — Validator accepted mistyped options

- Severity: low
- Finding: any argument other than `--strict` silently selected non-strict validation, so a typo could bypass secret/deployment checks.
- Fix: argument parsing now accepts only no option or exactly one `--strict`; anything else exits with usage and status 2.

### P1-03 — `agentctl` did not validate its credential input

- Severity: medium
- Finding: an unreadable, missing, empty, short, or duplicate key entry could become a malformed Authorization header and produce confusing downstream failures.
- Fix: `agentctl` now requires a readable key file, deliberately selects the last key assignment, and rejects keys shorter than 32 characters before making a request.

### P1-04 — Authentication documentation was inaccurate

- Severity: low
- Finding: documentation said every gateway call was authenticated, while `/health`, `/openapi.json`, and the HTML dashboard shell are intentionally public inside the trusted network boundary.
- Fix: documentation now distinguishes authenticated tool/data endpoints from intentionally unauthenticated discovery and health endpoints.

## Verification

- Fixes are subject to the cumulative validation recorded in pass 4.
