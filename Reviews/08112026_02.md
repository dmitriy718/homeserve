# Review pass 2 — security and trust boundaries

Date: 2026-08-11  
Depth: 2× baseline  
Perspective: adversarial requests, credential exposure, container isolation, and lateral movement

## Scope and method

Built on pass 1 by tracing data and credentials across the client, HTTP gateway, subprocess environment, Docker networks, bind mounts, and browser-test container. Reviewed every gateway route and mutation, rendered Compose security settings, and compared documented versus effective authentication boundaries.

## Findings and fixes

### P2-01 — Shell jobs inherited the gateway credential

- Severity: high
- Finding: `shell_exec` passed the complete container environment into arbitrary project commands. That included `AGENT_GATEWAY_KEY`, allowing a command or prompt-injected tool call to print or exfiltrate the gateway credential.
- Fix: shell jobs now receive a strict allowlist containing only `PATH`, a writable cache `HOME`, `TMPDIR`, locale, and project name. Secrets and unrelated service configuration are excluded.

### P2-02 — Privileged tool discovery was unauthenticated

- Severity: medium
- Finding: FastAPI exposed `/docs`, `/redoc`, `/openapi.json`, and `/tools` without authentication, disclosing the full privileged shell/filesystem API to any trusted-network client.
- Fix: automatic docs are disabled. `/openapi.json` and `/tools` are explicit authenticated routes, preserving authorized Open WebUI and `agentctl` discovery while reducing unauthenticated exposure.

### P2-03 — Filesystem audit/resource handling was incomplete

- Severity: medium
- Finding: directory creation and file deletion were not audited; `fs_hash` could read an arbitrarily large path and returned internal errors for non-files; directory listing followed symlinks for metadata.
- Fix: mkdir/delete actions are audited, hashes require a regular file and are capped at 100 MB, missing files receive deliberate HTTP errors, and listings use `lstat` to report symlinks without following them.

### P2-04 — URL credentials could enter audit records

- Severity: medium
- Finding: the HTTP inspection tool accepted `https://user:password@host/` and logged the entire URL. Fragments and unbounded URL/hostname inputs also provided unnecessary parser and log surface.
- Fix: embedded URL credentials and fragments are rejected; URLs and hostnames now have explicit length bounds, and TLS ports are constrained to 1–65535.

### P2-05 — Gateway and browser test shared a network

- Severity: medium
- Finding: the always-on gateway was attached to the disposable Playwright `dev` network, unnecessarily creating a lateral path between browser content and the agent service.
- Fix: the gateway was removed from `dev`; it remains on only the AI and monitoring networks required for its service-transparency functions.

### P2-06 — Browser test shared host IPC

- Severity: medium
- Finding: Playwright used `ipc: host`, exposing host IPC resources to browser processes.
- Fix: host IPC sharing was replaced with a private 1 GiB shared-memory allocation, retaining Chromium stability without crossing the host IPC boundary.

## Verification

- Compose renders with the gateway absent from `dev`, Playwright without host IPC, and a 1 GiB private shared-memory allocation.
- Gateway runtime/authentication tests and cumulative checks are recorded in pass 4.

## Residual considerations

- Authenticated shell execution remains intentionally powerful inside the scoped workspace and can access networks attached to the gateway. It still has no Docker socket, host root, SSH keys, or sudo.
- The LAN/Tailscale firewall remains part of the gateway trust boundary; TLS termination was not added because no public exposure was authorized.
